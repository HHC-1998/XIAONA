> 本目录按日期归档 XIAONA 开发过程中遇到的问题与解决方案，作为项目问题台账。当日所有代码修改、排查结论均反哺至此，同时同步更新到对应的原计划文档。

## 一、飞书绑定改造 + 文档-代码全量对齐（2026-08-18 实施定稿）

### 背景需求

用户 2026-08-17 定稿的新机制（见 8月17日台账「七」）与 2026-08-18 的全量核对结论一起实施：

1. **飞书影子账号机制彻底废弃**：未绑定 open_id 不创建账号、不调 LLM，只回 0 token 引导；存量 `feishu_` 影子账号用一次性脚本清理。
2. **飞书账号绑定改为对话框内三步**：手机号（确定目标账号）→ 密码（身份确认）→ 短信验证码（证明手机归属），一步一问、5 分钟内存超时；一个小娜账号（一个手机号）可绑多个飞书 open_id。
3. **设置页改造**：未绑定显示三输入框补录手机号/密码；已绑定显示绑定身份列表（open_id 后 8 位 + 绑定时间 + 最后活跃），每项可「解绑」「修改密码」（均需手机号 + 验证码确认）。
4. **文档-代码全量对齐**：核对 01 文件夹 12 份 + 02 文件夹 3 份文档与代码的全部不一致项并修复（含代码缺陷：JSON 导出缺 attachments、CLI require_login 死代码、审核意见未回传执行者等）。

### 根因分析

- **500 根因**：影子账号机制为未绑定 open_id 自动建号并调 LLM，但影子账号无模型配置 → `ChatModelNotConfigured` 500，同时陌生人白耗主人 token。
- **文档漂移**：8月17日大量设计变更（飞书绑定、多 Agent、导出字段、免密软删除等）未同步到全部文档，文档与代码出现多处不一致（含"待实施"标注滞留）。

### 解决方案（实施全貌）

**后端核心（P0）**

1. **数据模型**：`FeishuUserMap.feishu_user_id` 去 `unique=True`（一账号多 open_id），新增 `bound_at`；`User.phone`/`last_active_at`/`last_reminded_at` 注释更新（影子废弃后仅活跃统计）；`AgentTask` 删 `is_shadow` 列；`AgentRunLog.round` 注释改「executor 工具轮次 / 审核 reject 记录 retry 次数」。
2. **迁移**：`database._apply_light_migrations()` 加 `DROP CONSTRAINT IF EXISTS feishu_user_map_feishu_user_id_key`（SQLite 无该约束时忽略）+ 补 `bound_at TIMESTAMP` 列。
3. **会话映射只查不建**：`feishu_session_map.py` 重写为 `get_feishu_bind_user`（未绑定返回 None）/ `bind_feishu_user`（幂等写映射）/ `ensure_feishu_session`（仅绑定用户建会话 + 刷新活跃）；删除 `get_or_create_user_by_feishu` 自动建号。
4. **绑定状态机 + 0 token 引导**：`feishu.py` 重写——`process_feishu_event` 开头绑定校验分流；新增 `_BIND_STATE`（open_id → `{step, phone, expire}`，5 分钟 TTL）、`_handle_bind_turn` / `_bind_step_phone` / `_bind_step_password` / `_bind_step_code` 三步；密码用 `auth.verify_password`、验证码用 `send_sms_code` / `verify_sms_code`（与注册/登录同源）；**密码/验证码只存在于内存链路、不落库不进日志**；删除 `is_shadow_account` / `_shadow_reminder` / `_task_shadow_notice` 及全部调用；修正模块 docstring（先解密→challenge→验签）。
5. **清理影子机制残留**：删除 `shadow_cleaner.py`；`main.py` 删 `_shadow_cleanup_loop`；`config.py` / `.env.example` 删 `SHADOW_TTL_DAYS` / `SHADOW_REMIND_INTERVAL_HOURS` / `SHADOW_CLEANUP_INTERVAL_HOURS`；agent 包全部移除 `is_shadow`（service `_create_task`/`_latest_pending`/`_confirm`/handle、workflow `_load_task`/`start_task_async`、api/agent `_task_dict`）。
6. **设置页 API**：`GET /api/settings/feishu-bind-status`（`phone_masked` + `bound: [{open_id_short, bound_at, last_active_at}]`）、`POST /api/settings/feishu-unbind`（手机号+验证码确认，只删映射保留三层记忆）、`POST /api/settings/change-password`（手机号+验证码+新密码 ≥6 位）；`bind-phone` 语境更新为「补录手机号/密码」，不再承担补建 open_id 关联。

**其他代码缺陷修复**

- `sessions.py` 导出 JSON 补 `"attachments": m.attachments or ""`。
- `cli/xiaona.py`：`new / start / continue / history / export / voice` 开头调用 `require_login(cfg)`（此前死代码未调用，未登录会裸 HTTP 错误）。
- `workflow.py`：打回重做时 `result["issues"]` 并入下一轮 `refined["review_issues"]`（executor 下一轮读取作为约束）；`AgentRunLog.round` 传真实轮次；`for attempt in range(1 + AGENT_MAX_RETRY)` 读配置；`executor.py` 用 `AGENT_MAX_TOOL_ROUNDS`（替换硬编码 6）。

**前端**

- `settings.js` 新增 `getFeishuBindStatus` / `unbindFeishu` / `changePassword`。
- `Settings.jsx` 账号绑定区块重构：未绑定 → 三输入框 + 作用说明 + 引导「真正绑定在飞书对话框完成」；已绑定 → 绑定身份列表（open_id 后 8 位 + 绑定时间 + 最近活跃）+ 每项「解绑」「修改密码」确认面板（手机号 + 验证码，mock 自动填入）。

**一次性脚本**

- `backend/scripts/cleanup_shadow_accounts.py`：删 `phone LIKE 'feishu_%'` 账号三层数据（SQL 消息/会话/任务 + 映射行 + Chroma collection + Neo4j 图谱），`--dry-run` 支持；执行后删除脚本。
  - **FK 删除顺序修复**：首次正式执行报 `feishu_session_map_session_id_fkey` 外键冲突——原实现先删 `sessions` 再删 `feishu_session_map`，但映射表的 `session_id` 外键引用 `sessions.id`。修复为先删引用方（`feishu_session_map` 按 `session_id` 与 `feishu_user_id` 两路）再删 `sessions`。dry-run 验证 1 个存量影子账号（sessions=1/messages=0/tasks=0/映射 1），正式执行成功（SQL + Chroma + Neo4j 三层清理）。

**文档反哺（15 份 + 台账）**

- 01 文件夹 12 份全部按「文档-代码全量核对」清单反哺（见 8月17日台账「七」与本次改动），重点：10 号飞书文档「待实施」→「已实施」、新绑定状态机/API 描述、映射模型去 unique + bound_at、技术栈改纯 SHA-256；05 前端补五键分配/回退链/新 API/onTaskStarted；02 长期记忆补 `_flatten_chroma` + forgetter to_thread；04 语音补大小预检/OpenAI prompt/timeout=60/TTS 422；09 改免密软删除；07 补 attachments/User 列；11 CLI 对齐 require_login；12 恢复 Excel 行去 chatApi.send。
